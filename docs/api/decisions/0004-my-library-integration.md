# ADR 0004: 내 서재 도서 CRUD API(GET /api/v1/library/books) 연동 및 올인원 독서 비서 구축

- **상태**: Accepted
- **날짜**: 2026-08-28
- **관련 티켓**: CLIAR-152
- **참여**: 오케스트레이터 및 AI 탐색 도메인

---

## 1. 배경 및 맥락
기존 DPYB 서비스에서는 사용자가 [도서 추천]과 [내 서재 검색/관리] 모드를 UI에서 수동으로 전환해야 했으며, 복합 의도(예: "내 서재에 있는 SF 소설이랑 비슷한 새로운 책 추천해줘")를 처리할 수 없었다.
이를 해결하기 위해 프론트엔드의 수동 모드 분기를 제거하고, 단일 오케스트레이터 에이전트(블루/슈빌)가 자연어 의도에 따라 **내 서재 검색**, **사서 상담**, **외부 도서 추천**을 자율 라우팅 및 연쇄 실행하는 **"Zero-Friction 올인원 독서 비서 (Unified Agent Assistant)"** 아키텍처를 도입하기로 결정하였다.

---

## 2. 결정 사항

### 2.1 HTTP 프록시 도구 패턴 채택 (`SearchMyLibraryTool`)
- `backend-discovery`는 서재 도서 데이터를 자체 DB에 복제하지 않고, 기존 서재 CRUD 마이크로서비스(`backend-book`)의 `GET /api/v1/library/books` API를 호출하는 HTTP 프록시 도구(`SearchMyLibraryTool`)를 구현한다.
- 인증 토큰(`Authorization: Bearer <token>`)은 클라이언트 요청에서 추출하여 서비스 레이어의 클로저를 통해 도구 함수 내부로 안전하게 주입한다. LLM은 검색 키워드 및 조건(`query`, `author`, `reading_status`)만 다루며, 사용자 식별자나 인증 토큰을 직접 조작하지 않아 IDOR 취약점을 원천 방어한다.

### 2.2 오케스트레이터 자율 라우팅 및 복합 체이닝 지원
- **단순 서재 조회**: `search_my_library` 도구만 호출하여 제목, 저자, 독서 상태, 진행률 정보를 자연어로 안내.
- **도서 추천**: `consult_librarian` (신호 분석) ➔ `recommend_books` (웹 검색 및 마크다운 카드 생성).
- **복합 의도 (서재 기반 추천)**: [1단계: `search_my_library`]로 서재 도서 확인 ➔ [2단계: `recommend_books`] 연쇄 실행.

### 2.3 Fallback 결합 안전장치
- 오케스트레이터의 도구 결과(`toolResult`) 결합 안전장치를 화이트리스트 방식(`has_book_card = "### 📖" in tool_result`)으로 제한하여, 서재 검색 원시 텍스트가 답변 본문 뒤에 무차별 중복 결합되는 현상을 원천 방어한다.

---

## 3. 파급 효과
- **긍정적 효과**:
  - 프론트엔드 모드 선택 제거 및 단일 자연어 입력창으로 사용자 경험(Zero-Friction) 극대화.
  - 내 서재 문맥을 파악한 고도화된 개인화 도서 추천 가능.
  - 마이크로서비스 간 단일 진실 공급원(SSOT) 유지 (Discovery 자체 서재 DB 불필요).
- **고려 사항**:
  - 서재 API 호출 지연에 대비한 타임아웃(10초) 및 에러 발생 시 graceful fallback 처리 완료.
